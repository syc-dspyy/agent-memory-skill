# 检索协议：漏斗（常驻 → 深层 → 浅层 → 向量）

> v1.3：目录分深浅两层后，漏斗从三级变四级——**L1.5 浅层**是新增的缓冲级。
> 详见 `index-tiering.md`。

> 读这份的时机：检索结果不对、想接向量库、或要判断该不该动用 L2。

## 为什么必须目录优先

向量检索在这套系统里是**兜底，不是首选**。三个理由：

1. **记忆目录是人写的、带判断的**。一行"项目延期 → 客户投诉"的摘要，语义相似度未必高，但因果是对的。
2. **成本**。L0/L1 是读文件，零算力；L2 要 embed、要检索、要重排。
3. **可解释**。目录命中能直接指给用户"我看的是这一行"；向量命中说不清为什么。

**反面教训**：不设门槛直接用向量检索，会退化成"每次都检索、每次结果都差不多"，还把目录架空了。

## L0 常驻加载（每次会话必做）

会话开始，**先验身份**（persona 第四节 / rules.md R3.1），再无条件读取：

```
main/persona.md      ← 我是谁 / 主人档案 / 我们的关系 / 身份识别
main/rules.md        ← R1–R14 规范规则（v1.1 取代 boundaries.md）
main/index.md        ← ★深层记忆目录（近期 + 重要）
                        ✗ 浅层 index-shallow.md 不在这里——它不常驻，按需才读
```

身份判定为「存疑」或「非本人」时**不加载记忆内容**，只做通用回答（降权）。

- 成本固定约 1–3K token（取决于 index 行数）
- **不受上下文压缩影响**——压缩后重新读一次即可恢复，这是本方案防失忆的根本
- 若 index.md 超过 200 行，拆成按年/按主题分文件，`index.md` 只留分表指针

## L1 定向查找

**Step 1 — 扫记忆目录**：在 `index.md` 里按关键词、日期、情绪、关联方法四列找。
**Step 2 — 命中则直达**：读对应 `facts/events/*.md`，再顺 `links.md` 找关联事件。
**Step 3 — 扫经验层**：看 `experience/methodology/` 和 `qa-templates/` 的文件名，判断有无现成做法或答案。

判据很松：**目录里有任何一行相关，就算命中**，哪怕不确定——读一个文件的成本远低于一次向量检索。

## L1.5 浅层目录（按需，v1.3 新增）

**进入条件（两条同时满足）**：

1. L1 深层目录**没有**匹配行
2. 问题确实指向**久远的事**或**日常小事**（不是近期要务）

动作：读 `main/index-shallow.md`，命中则照常直达事件详情；**在回复中说明「深层未找到，已查浅层」**。

**为什么需要这一级**：

- 比向量检索便宜——只是读一个 Markdown 文件
- 比直接说"没找到"靠谱——其实记得，只是不在常驻区
- 少了这一级，久远记忆会直接掉进"AI 说它忘了"的坑里（违反 R1.2 的精神）

浅层也空手而归，才进 L2。

## L2 向量检索（仅在前三级落空后）

**进入 L2 必须同时满足**：
- L0 常驻已读
- L1 目录无任何相关行
- 该问题确实需要细节（不是一句常识能答的）

进入时要**在回复中显式说明**：「记忆目录未命中，已对事实层做向量检索」。这条透明要求是为了让你自己和用户都能发现"目录是不是该补一行了"。

### 三种落地方案（按库规模选）

| 规模 | 方案 | 依赖 |
|---|---|---|
| 事件 < 100 篇 | `grep -r` / 关键词匹配兜底 | 零依赖，**推荐起步** |
| 100–1000 篇 | 本地 SQLite FTS5 + 可选向量扩展 | 见下 |
| > 1000 篇 | 外部向量库（Qdrant / pgvector / LanceDB） | 见 `integrations/platforms.md` |

**向量库选型若需决策，参考《向量数据库选型笔记》，本技能不代做选型。**

### 索引的性质（铁律）

```
facts/*.md  ←  真相，Markdown，进 git
     ↓ 派生
向量索引     ←  派生物，可删，可重建
```

- 索引损坏 = 重建，不算丢
- **禁止**出现"只有向量库里有、文件里没有"的记忆
- 重建命令：`python3 scripts/memory_index.py --rebuild`

## 降级策略

| 情况 | 怎么做 |
|---|---|
| 向量库不可用 / 服务没起 | 自动降级到 `grep -r` 关键词检索，并在回复中说明已降级 |
| 目录命中但详情文件丢失 | 报**断链**，不要拿索引摘要当详情回答（摘要可能过时） |
| 三级都没找到 | **如实说没找到**。禁止编造、禁止"根据记忆推测" |
| 找到但记忆过期（事件有后续） | 顺 `links.md` 找后续事件，以最新的为准，并说明演变 |

最后一条尤其重要：本系统**保留旧事件不删除**（不像数据库方案会覆盖），所以你必须通过 `links.md` 判断哪个是最新状态。

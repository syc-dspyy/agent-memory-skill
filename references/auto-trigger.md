# 自动触发规范：AI 自己知道何时存、何时读

> 读这份的时机：**每次会话开始前扫一遍**（初期），直到触发条件内化为止。
> 对应 `main/rules.md` 的 **R11**。留存分级见 `retention-spec.md`（R12）。

## 一、为什么必须自动触发

记忆库最大的失败形态不是"存错了"，而是**根本没触发**：

- **靠用户说"记住这个"** → 90% 该记的没记。用户不会每次都记得下指令，他只是在正常说话。
- **靠用户说"去查记忆"** → 记忆库形同虚设。用户自己都忘了 AI 有记忆，等于白建。
- **上下文一清空就断片** → 新会话不知道自己有记忆库，从头开始当陌生人。

所以：**读写记忆是规则驱动，不是指令驱动。**用户说"记住"只是众多触发信号中的一种（T9），不是唯一入口。

一句话目标：**主人正常说话，我自动完成存取；主人不用管记忆库，但记忆库一直在运转。**

## 二、保存触发信号 T1–T11

**出现任一信号 → 不等指令，自动执行对应写入动作。**

| # | 触发信号 | 典型话术 / 场景 | 自动动作 | 落点 | 需确认 |
|---|---|---|---|---|---|
| **T1** | 透露偏好 / 价值观 / 忌讳 | "我不喜欢长篇大论""别用 emoji""结论先行" | 更新主人段偏好与雷区 | `main/persona.md` | ✅ 复述确认 |
| **T2** | 纠正我 | "不对，应该先停服务再备份" | 写事件；若可复用则提炼方法论 | `facts/events/` + `experience/methodology/` | 事件否 / persona 是 |
| **T3** | 达成决策 / 任务收口 | 方案敲定、选型定了、项目上线 | 写事件（五段齐全） | `facts/events/` | 否 |
| **T4** | 出现强情绪 | 生气、兴奋、焦虑、后悔、纠结 | 写事件，**重点写感受与未解隐患** | `facts/events/` | 否 |
| **T5** | 教方法 / 给模板 | "以后就按这个格式写""先 A 再 B 再 C" | 写 SOP（触发场景/步骤/**验收标准**） | `experience/methodology/` | 否 |
| **T6** | 同一问题问到第 3 次 | 反复问同一个流程 / 同一个答案 | 写问答模板（问题模式/答案/**适用边界**） | `experience/qa-templates/` | 否 |
| **T7** | 学到新知识 | "原来 X 的原理是 Y" | 已绑知识库 → 写库 + 本地留指针；未绑 → `facts/knowledge/` | 见 `.memory-config.yaml` | 否 |
| **T8** | 出现人物 / 关系 / 实体 | "我同事""我妈""XX 项目""我们老板" | 关系类 → persona（确认）；事件涉及 → `involves` 关联 | `persona.md` / `events/` | persona 是 |
| **T9** | 显式指令 | "记住这件事""别忘了我说过" | 立即走写入判定树 | 按分流 | 否 |
| **T10** | 会话收尾 / 长会话分段 | 用户说"先这样""今天到这"；或已聊很久 | **收尾盘点**：本轮有哪些值得记的，补写 | `facts/events/` | 否 |
| **T11** | 踩坑 / 失败 / 试错 | 方案行不通、试错失败 | 写事件 + 提炼"不要这样做"进方法论 | `events/` + `methodology/` | 否 |

### 三条执行细则

1. **T1 / T8 改 `persona.md` 必须复述确认**（R10.1）。其余层可直接写。
2. **T10 收尾盘点是防止「漏记」的最后一道闸**。长会话结束前主动回顾：这轮主人透露了什么偏好？做了什么决定？纠正了我什么？——补写进去。
3. **T6 的门槛是「第 3 次」**，不是第一次。第一次直接回答，第二次留意，第三次才入库（R8.4 防凑数）。

## 三、读取触发信号 U1–U8

**出现任一信号 → 不等指令，自动执行检索。**

| # | 触发信号 | 自动动作 | 漏斗级别 |
|---|---|---|---|
| **U1** | 会话开始（无条件） | 先验身份 → 读 `main/` 全量（persona + rules + index） | L0 |
| **U2** | 提到"上次 / 之前 / 那次 / 以前 / 记得吗" | 检索 `index.md` → 读详情 → 顺 `links.md` 找关联 | L1 |
| **U3** | 出现人名 / 项目名 / 专有名词 / 日期 | 检索 `index.md`，命中即读 | L1 |
| **U4** | 问"我是谁""你知道我吗""我们什么关系" | 读 persona 第二、三段 | L0 |
| **U5** | 遇到同类任务 / 重复场景 | 扫 `experience/` 标题，有现成做法直接用 | L1 |
| **U6** | "你怎么又忘了""我不是说过" | 立即检索并承认，**禁止辩解** | L1→L2 |
| **U7** | 要我做决策 / 给建议 / 写方案 | 先读主人偏好 + 相关历史事件，再开口 | L1 |
| **U8** | 当前情境与历史模式相似 | **主动关联提醒**："上次你遇到类似情况时…" | L1 |

### U6 的正确姿势

被说"你又忘了"时，**第一反应是检索，不是道歉也不是辩解**：

```
❌ "抱歉，我记性不好"           → 没检索就认输
❌ "你说过吗？我不记得了"         → 反问用户，把检索责任推回去
✅ （先检索 index）→ "查到了，你说的是 X（main/index.md 第 N 行）。
    我这次没自动去查，是我的问题。以后这类情况我会先查目录。"
```

**"没检索"和"没找到"是两回事。** U6 最常见的错误就是还没检索就先说没有。

### U8 是记忆库真正的价值

前七个信号都是"被动作答"，U8 是**主动联想**——主人没问，但你发现当前情境和历史某件事像，主动提醒。这才是"养出的人格"该有的样子，而不是一个被动的数据库。

## 四、每轮对话的自动判定流程

```
每一轮对话开始
   ↓
① 身份判定（R3）
   ├─ ✅ 主人 → 继续
   ├─ ⚠️ 存疑 → 降权，本轮不读不写
   └─ ❌ 非本人 → 拒绝，不透露记忆存在
   ↓
② 扫读取触发：本轮命中 U1–U8 吗？
   └─ 命中 → 执行 L0 → L1 → L2（上一级命中不往下走，R6.3）
   ↓
③ 正常回应 / 完成任务
   ↓
④ 扫保存触发：本轮命中 T1–T11 吗？
   └─ 命中 → 走写入判定树（SKILL.md 第三节）
        → 选模板 → 写文件 → 更新 index.md + links.md
        → 跑 memory_check.py
   ↓
⑤ 会话收尾：T10 盘点补漏
```

**关键点：第 ②④ 步是「扫描信号」，不是「等指令」。** 每轮都扫，扫到就做。

## 五、正反例

### ✅ 正例

| 场景 | 正确反应 |
|---|---|
| 主人："我讨厌别人啰嗦" | 自动触发 T1 → "我记下你的偏好：讨厌啰嗦，以后我结论先行。要写进主人档案吗？"（确认后写入 persona） |
| 主人纠正："不是先备份，是先停服务" | 自动 T2 → 写事件；判断可复用 → 提议提炼成方法论 SOP |
| 主人："上次那个项目怎么定的来着？" | 自动 U2 → 检索 index → 命中 → 读详情 → 回答并标注来源路径 |
| 主人要我做技术选型 | 自动 U7 → 先读主人偏好（是否偏好轻量方案）+ 相关历史事件，再给建议 |
| 当前任务和历史某次失败很像 | 自动 U8 → "上次你这么做的时候踩过 X 的坑（见 xxx.md），这次要不要避开？" |

### ❌ 反例（最常见的四种失败）

| 失败 | 为什么错 |
|---|---|
| 主人说了偏好，我只在当前会话遵守，下次又忘 | **违反 T1**。这是最典型的失败——听到了但没入库，等于没听到 |
| 主人提到"上次"，我直接说"我不记得了" | **违反 U2**。没检索就说没有 ≠ 真的没有。必须检索后再回答 |
| 每次都要主人说"你去查一下记忆库" | **违反常驻锚点（R13）**。说明 AI 不知道自己有记忆库，锚点没注入或没生效 |
| 什么都往里存 | **违反留存分级（R12）**。库会变成噪音，检索命中率下降，最终没人信它 |

## 六、与身份识别的配合

自动触发有个前提：**确认对方是主人**。

| 场景 | 自动保存行为 |
|---|---|
| ✅ 已确认为主人 | 全自动触发 T1–T11 |
| ⚠️ 存疑 | **不写任何记忆**（R3.1 降权） |
| ❌ 非本人 / 群聊里的其他人 | **不写**，且不透露记忆库存在（R3.3） |
| MCP / 外部接口 | 默认按存疑，**不自动保存**；需主人当场过 S 级提权，且只对当前会话有效 |

**理由是防污染**：如果陌生人在群里说的话也被自动记住，人格和事实层会迅速失真。自动保存是特权，只对确认的主人开放。

## 七、怎么让 AI 永远记得「我有记忆库」

靠 `rules.md` 不够——规则文件本身也要被读到才有用。所以需要**常驻锚点（R13）**：

把一段 3–5 行的记忆库指针，注入到 AI **每次会话必然加载**的文件里
（`AGENTS.md` / `CLAUDE.md` / 工作区 `MEMORY.md` / `.cursorrules` 等）。

```bash
python3 scripts/memory_anchor.py --root "D:/memory" --inject "D:/项目/AGENTS.md"
python3 scripts/memory_anchor.py --check  "D:/项目/AGENTS.md"
```

注入后，即使上下文清空、新开会话，AI 加载 `AGENTS.md` 时就会看到"我有记忆库，在什么时机必须读、必须写"，从而自动恢复记忆行为。详见 `scripts/memory_anchor.py` 与 R13。

## 八、自检：自动触发生效了吗

每周问自己三个问题，任一为"否"就说明机制没跑通：

1. 这周主人说过偏好，我**当场**就存了吗？（不是事后补、不是下次又问一遍）
2. 主人提到"上次"时，我是**先检索**再回答的吗？
3. 有没有出现过"主人提醒我去查记忆库"的情况？（有 → 锚点或规则没内化）
